<Note>
Configure your source database before you create the ClickPipe. If you haven't done so yet, follow the configuration guide for your [data source](/integrations/clickpipes/mysql#supported-data-sources).
</Note>

<Steps>
<Step title="Select the data source" id="1-select-the-data-source">

**1.** Make sure you're logged in to your ClickHouse Cloud account. If you don't have an account yet, you can sign up [here](https://cloud.clickhouse.com/).

**2.** In the ClickHouse Cloud console, navigate to your ClickHouse Cloud service.

<Image img="/images/integrations/data-ingestion/clickpipes/cp_service.webp" alt="ClickPipes service" size="lg" border/>

**3.** Select **Data sources** in the left-side menu and click **Set up a ClickPipe**.

<Image img="/images/integrations/data-ingestion/clickpipes/cp_step0.webp" alt="Select imports" size="lg" border/>

**4.** Select the tile that matches your source. Amazon RDS, Amazon Aurora and Cloud SQL each have a dedicated tile; for any other deployment, select `MySQL CDC` or `MariaDB CDC`.

<Image img="/images/integrations/data-ingestion/clickpipes/mysql/mysql-tile.webp" alt="Select MySQL" size="lg" border/>

</Step>
<Step title="Add your source database connection" id="2-add-your-source-database-connection">

**1.** Fill in the connection details for the source database you configured in the previous guide.

<Info>
Before you add your connection details, make sure you have allowed the ClickPipes IP addresses in your firewall rules. See the [list of ClickPipes IP addresses](/integrations/clickpipes/networking/static-ips), and the configuration guide for your data source.
</Info>

<Image img="/images/integrations/data-ingestion/clickpipes/mysql/mysql-connection-details.webp" alt="Fill in connection details" size="lg" border/>

<Tip>
For Amazon RDS and Amazon Aurora sources, you can authenticate with an [IAM role](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html) instead of a password by selecting `IAM role` as the authentication method.
</Tip>

**2.** _(Optional)_ Change the TLS settings.

**3.** _(Optional)_ Set up SSH tunneling, if your source database isn't publicly accessible.

   a. Enable the **Use SSH Tunnelling** toggle.

   b. Fill in the SSH connection details.

   <Image img="/images/integrations/data-ingestion/clickpipes/postgres/ssh-tunnel.jpg" alt="SSH tunneling" size="lg" border/>

<Step title="Configure advanced settings" id="3-configure-advanced-settings">

You can adjust the advanced settings if needed. Each setting is described below:

- **Sync interval**: the interval at which ClickPipes polls the source database for changes. This has an impact on the destination ClickHouse service; for cost-sensitive use cases, we recommend a higher value (over `3600`).
- **Parallel threads for initial load**: the number of parallel workers used to fetch the initial snapshot. Useful to control resource usage when you have a large number of tables. This setting is per-table.
- **Pull batch size**: the number of rows to fetch in a single batch. This is a best-effort setting and may not be respected in all cases.
- **Snapshot number of rows per partition**: the number of rows fetched in each partition during the initial snapshot.
- **Snapshot number of tables in parallel**: the number of tables fetched in parallel during the initial snapshot.
- **Server ID**: the server ID used for binlog replication. If unset, ClickPipes generates a random server ID that might change over the ClickPipe lifecycle. Set it to deterministically identify your ClickPipe on the source server.
